# 术语表（Glossary）

recon-helper 涉及的核心概念与术语，按功能域分组。

## 数据与读取

- **Table（表格模型）**：读取器输出的统一内存结构，包含列名、行记录与列类型，是所有核对功能的输入。
- **读取器（Reader）**：把外部文件转成 Table 的组件，支持 xlsx、csv、json、tsv、固定宽度五种格式。
- **编码检测（Encoding Detection）**：自动识别文本文件字符集（utf-8 / gbk / utf-16 等）的过程，避免中文乱码导致的解析失败。
- **列类型推断（Type Inference）**：根据列内容自动判断该列是文本、数值、日期还是布尔类型。
- **固定宽度文件（Fixed-width File）**：每列按字符位置对齐而非分隔符划分的老式数据文件。

## 规则与引擎

- **规则（Rule）**：一条对账指令，声明"哪两张表、按什么键关联、比较哪些列、允许多大误差"，以 YAML 编写。
- **规则引擎（Engine）**：读取规则文件并执行核对的核心组件，输出差异清单。
- **关联键（Join Key）**：两张表之间用于对齐行的列（如订单号、员工编号），支持复合键（多列组合）。
- **过滤器（Filter）**：在核对前缩小数据范围的配置，例如只比对某年份或排除某部门。
- **字段转换（Transform）**：比对前对列值做的换算（如万元转元、文本标准化、空值策略）。

## 容差与口径

- **绝对容差（Absolute Tolerance）**：允许的最大差额绝对值，例如差 1 元以内视为一致。
- **相对容差（Relative Tolerance）**：允许的最大差异比例，例如 0.5% 以内视为一致。
- **多级容差（Tolerance Tiers）**：按金额档位设置不同容差的机制（金额越大允许的绝对误差越大）。
- **舍入口径（Rounding Mode）**：先四舍五入再比较，或直接比较原始值，输出时注明所用口径。
- **优先级（Priority）**：多条规则命中同一单元格时的仲裁顺序，数字大者优先。

## 金融核对特性

- **合计核对（Total Check）**：明细数据按列求和后与汇总表的合计行比对。
- **勾稽链（Chain Check）**：A 表的期末值必须等于 B 表期初值，支持三张以上表格顺序勾稽。
- **缺失检测（Missing Detection）**：按时间列检查序列完整性，自动发现缺失的月份或日期。
- **环比/同比（Period Check）**：本期数据与上月/去年同期对比，超出波动比例标记异常。
- **账龄分析（Aging Analysis）**：按账期分段（30/60/90/180/360 天）统计金额占比及结构变化。

## 输出与报告

- **差异清单（Diff List）**：核对结果的核心输出，逐条列出不一致的位置与差值。
- **严重程度（Severity）**：差异的分级——致命（缺数据）、严重（超容差）、提示（容差内）。
- **复核状态（Review Status）**：人工对差异条目的处理标记——未处理/已确认无误/已修复。
- **增量核对（Incremental）**：通过文件内容哈希指纹跳过未变化文件，只核对变化部分。
- **快照（Snapshot）**：每次核对的输入指纹、规则与结果的完整记录，支持回放对比。

## 运行与配置

- **Profile（配置预设）**：一组预设参数（严格/宽松），一键切换容差与规则开关。
- **插件（Plugin）**：用户放在 plugins/ 目录的自定义核对脚本，按约定签名自动发现执行。
- **指纹（Fingerprint）**：文件内容的哈希值，用于增量核对与一致性校验。
- **计划编排（Plan）**：多个规则文件按依赖顺序执行的调度配置（depends_on）。
- **dryrun（模拟运行）**：只执行单条规则并输出中间计算过程的调试模式。
- **质量评分（Quality Score）**：对输入表的四维加权评分（空值率/类型错误率/重复率/主键唯一性）。
- **通知渠道（Notify Channel）**：核对完成后推送摘要的途径，支持 Webhook 与 SMTP 邮件。
