# FAQ

**为什么同一条规则没有输出？** 两边完全一致或差异在容差范围内时，结果为空或状态为 `within_tolerance`。

**为什么 XLSX 公式报错？** 工具拒绝未核验的公式缓存值，请先将公式转换为已确认的数值。

**增量报告为什么跳过？** 规则文件和所有参与文件的 SHA-256 指纹没有变化，已有报告可直接复用。

**PDF 导出失败怎么办？** 安装 `reportlab`，然后调用 `recon.exporters.export_pdf`。

## 运行时问题

**CSV/TSV 中文乱码或出现解码错误怎么办？** 读取器会自动尝试常见编码；仍失败时运行 `recon read FILE --encoding gbk`、`utf-16` 或文件实际编码。不要只改终端字体，先确认文件字节编码；转换编码会改变文件内容和 SHA-256 指纹。

**多个任务同时写历史库时报 database locked 怎么办？** `recon_history.db` 使用 SQLite WAL 和 30 秒 busy timeout。避免多个独立进程同时初始化/迁移同一数据库；确认本地磁盘支持 SQLite 锁，等待短暂写入完成后重试。不要在网络共享盘上并发写同一个库。

**大文件内存还是偏高怎么办？** 流式读取器逐行读取 CSV、TSV 和 read-only XLSX，但引擎仍会构建主键索引；高基数数据集的索引会占用内存。先用 `recon bench FILE` 检查峰值，再按日期/部门拆分数据，或关闭 benchmark 的重复检测；不要把“流式”理解为整个核对过程零缓存。

**为什么指定超时后任务仍可能晚一点才停止？** `run --timeout` 在核对流程检查点检查期限，单个文件解析、系统 I/O 或某个长计算段结束后才会发现超时；它不是可中断的操作系统级强制终止。使用 `RECON_TIMEOUT` 返回码定位超时，先缩小范围或提高合理的秒数，再运行 `recon bench` 评估。

**为什么文件没改却没有命中增量指纹，或改了位置后无法复用？** 指纹按参与文件内容计算，但 SQLite 以传入的文件路径作为键。检查规则解析出的左右文件路径是否与前次一致，并确认内容、换行符和编码没有变化；移动/重命名文件即使内容相同也会被视为新路径。不要手工复制旧指纹到新路径来掩盖输入来源变化。
